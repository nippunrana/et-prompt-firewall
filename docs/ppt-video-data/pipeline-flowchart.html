ET Prompt Firewall: how the pipeline works

The firewall checks everything an AI agent reads, cuts out hidden instructions and names the attack type. Then it checks every action the agent tries to take.

Plain code (no AI) Small AI model, runs on our server Large language model (cloud)

1The big picture: two checkpoints

The agent never reads raw content, and it never acts without a check.

Incoming contentemail · web page · PDF · Word · image · chat message
→
Checkpoint 1
Content checkfinds the attack, names it, cuts it out
→
AI agentreads only the cleaned content
→
Checkpoint 2
Action checkis this action what the user asked for?
→
Tools runsend · forward · pay · delete
Why two? No content filter is unbeatable. Checkpoint 2 never reads the content, so an email cannot talk to it. It compares what the agent is about to do with what the user actually asked. An attack that slips past checkpoint 1 still has to get its action past checkpoint 2. An audit log records every decision from both.

2bEach step: what, why, when

“Why” means what this step catches that no other step can.

1Preparecode

What
Splits web pages and files into visible text and hidden parts (comments, white or tiny text, hidden elements). Undoes disguises like look-alike letters, invisible characters, Base64 and hex. Splits the text into sentences.
Why
Attackers hide instructions where people can’t see them. About 70% of real web attacks sit in HTML the browser never shows. We split, never strip: throwing hidden text away would delete the attack before anyone checks it.
When
Always, first.

2Rulescode · regex

What
Matches known attack phrases like “ignore previous instructions”. A strong rule is proof on its own. A weak rule (“send … to an address”) is only a hint, because normal email says that too.
Why
It is exact, explainable and impossible to argue with. It also names the attack type.
When
Always.

3Wolf Defenderlocal model · mmBERT

What
An AI model trained to spot prompt injection. It scores the whole text, then every 3-sentence window, then narrows down to the guilty sentence.
Why
It catches reworded attacks that no fixed phrase list would. It is multilingual: it caught a Hinglish attack at 0.99.
When
Always, on every window. One bad line in a long friendly email can’t hide in the average.

4Prompt Guard 2local model · Meta

What
A second detector from a different company, built differently. It almost never raises a false alarm.
Why
Agreement. When two different models flag the same spot, that is strong proof, so the text is cut without asking the AI judge. Two independent models rarely make the same mistake.
When
Always, alongside Wolf Defender.

5Languagelocal model · GlotLID

What
Flags lines that are not in English, including Hindi or Urdu typed in English letters (Hinglish). It never cuts anything. It only sends the input to the AI judge.
Why
The detectors are only proven on English. A low score on foreign text may mean “I can’t read this”, not “safe”. This step stops that from passing as clean.
When
Always. Why after the detectors? Order doesn’t matter: all four checks read the original text on their own. It isn’t a gate in front of them, because English text still needs them.

6Triagecode

What
Picks a lane. Clean if nothing was flagged. Otherwise the input is flagged and goes to the AI layers.
Why
Most real content is clean. It costs nothing and gets an instant answer, so we only pay for AI on suspicious content.
When
Always, after the four checks.

7JudgeGemma 4 31B

What
Reads the content and the flagged parts. It says if each part is an attack, names the type and quotes the exact words. Its prompt is hardened: the content is fenced off as data, and the judge must repeat a secret code.
Why
It understands meaning and intent. It is the only step that can clear a false alarm, but only a weak one. If it gets the secret code wrong, the content has taken it over, and the input is quarantined.
When
Only on flagged content. Usually about 7 s, hard limit 60 s.

8SandboxQwen3-next-80B

What
A deliberately gullible assistant reads the content with fake tools (send, pay, delete). Nothing ever runs. Code just watches what it tries to do.
Why
It gives proof by behaviour, not opinion: does this text actually make an agent act? The address it tries to send to shows exactly which sentence to cut.
When
Only on flagged content, at the same time as the judge. Usually about 2 s, hard limit 30 s.

9Decidecode

What
Combines every signal using fixed rules: strong signals are cut, and the judge settles weak ones (section 3).
Why
The content is written by the attacker. If an AI chose the next step, the content could steer the firewall. So code makes every decision, and the AIs only give evidence.
When
After the judge and the sandbox finish.

10Cutcode

What
Replaces each attack sentence with a visible marker naming the type. Then it removes every other sentence carrying the attacker’s email address or link (the “payload sweep”).
Why
One planted line shouldn’t cost the user a real email, so we keep the rest. Without the sweep, the attacker’s address survived in about 80% of real attacks.
When
When Decide finds an attack.

11Re-checkcode + local models

What
Runs the rules and both detectors on the cleaned text. It re-runs the sandbox too if it was fooled, except on the user’s own message. Anything left widens the cut.
Why
It proves the cleaning worked. A sentence-level cut can leave part of an attack behind.
When
After every cut. After two widenings, if the text is still bad, it is quarantined.

3How code decides: strong vs weak

This is the heart of the design. Fooling one layer is never enough.

Strong signal → cut on its own

The AI judge cannot overrule it.

  • A strong rule matches
  • Both detectors flag the same spot
  • The sandbox tried to use a tool (on outside content)
  • The judge says “attack” and its quote is really in the text

Weak signal → the judge decides

The judge can keep or clear each flagged part.

  • Only one detector flags it
  • A weak rule hint
  • The language check flags it
  • Something found only in hidden text
  • The sandbox acted on the user’s own message (a request is supposed to ask for actions)
Judge gets the secret code wrong → the content hijacked it → quarantine.
Judge is down or too slow → cut the detector flags anyway (when in doubt, block) and say so in the answer.

4Checkpoint 2: the action check

Plain code with no AI, and it never reads the content. It runs every time the agent tries an action with an outside effect (send, forward, pay, delete, run, fetch). It blocks the action if:

🔑 SecretsA password, API key, one-time code or the agent’s planted secret is in the outgoing data.
📍 ProvenanceThe recipient, link or account isn’t in the user’s request or contacts. It came from the content.
🎯 IntentThe user never asked for this kind of action. “Summarise my email” never needs a payment.

When an action is blocked, the agent is told why and carries on with the user’s real request.

6Four rules that make it hard to fool

1. Code decides, AI only advisesThe attacker writes the content. An AI that picks the next step could be steered by it. Code can’t.
2. The two AIs never talkA fooled sandbox repeats the attack word for word. If the judge read that, one hijacked model could steer the other.
3. When in doubt, blockJudge down: cut anyway. Firewall unreachable: the email is withheld and the action blocked.
4. No human in the loopNothing waits for approval. The audit log records every decision afterwards, storing a fingerprint of the text but never the text itself.
